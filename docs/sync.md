# 同步时冲突怎么处理

手机和电脑各自持有一份题库。点同步时，手机把整份快照 POST 到 `/api/sync`，服务端只取出**当前登录用户**的库，和这份快照合并，再写回这个用户。另一个账号的题不会被这次同步删掉或改掉。

两边记录用 `uid` 认作同一条。`uid` 相同才合并；不同就是两条新记录。

## 卡片：内容和进度分开比时间

一张卡片有两个时间：

- `content_at`：题面、答案、掌握程度改动的时间。
- `schedule_at`：复习评分改动间隔、到期日的时间。

合并时各自取更新的那一边，不整张覆盖。

| 字段 | 规则 |
| --- | --- |
| 问题、答案、掌握程度、掌握颜色 | `content_at` 更新的一边 |
| 难度、间隔天数、重复次数、到期日 | `schedule_at` 更新的一边 |
| 已学日期 `studied_days` | 两边的日期取并集，不丢任何一天 |

所以电脑上刚改完答案、手机上刚把这题标成「明天再来」，同步之后两边都会留下：新答案来自电脑，新的到期日来自手机。

时间字符串按字典序比较，格式是 `YYYY-MM-DDTHH:MM:SS`。缺时间的一边视为更旧。两边时间相同，则后参与合并的手机快照胜出（比较用 `>=`）。

## 笔记

同一 `uid` 的笔记只比 `updated_at`，更新的标题和正文整篇留下。

## 删除

删除笔记或卡片时会写一条墓碑：`kind`、`uid`、`deleted_at`，并且只属于当前用户。

- 墓碑比这条记录的内容时间（卡片还要比进度时间）更新：记录删掉，它的复习记录一起去掉。
- 记录在删除之后又被改过：墓碑作废，记录留着。

这样「一边删了、另一边后来又改过」不会把改动静默丢掉。

## 领域

同名领域合成一个，卡片和笔记改挂到留下的那个 `uid` 上。不同名的领域都保留。

## 复习记录

复习记录按自己的 `uid` 去重。同一个 `uid` 在两边都出现时，手机快照里的那条留下。卡片被墓碑删掉之后，指向它的复习记录不再保留。

## 和多用户的关系

同步接口要带登录令牌。服务端导出、合并、写回都限定在这个用户的领域上。甲的同步不会清空乙的卡片，两边也可以各自有一个同名领域。
